# Schema-3 semantic qualification candidate

This corpus is an enforce-shaped preregistration input for [EVC-10.1]. It
contains 20 clean negative variants and 20 independently source-reviewed
synthetic misaligned variants. The misaligned units keep executable reciprocal
trace declarations, so the semantic lane is measuring whether the evidence
supports the obligation rather than rediscovering missing syntax.

The corpus is not stronger-policy authority. There is no analyzer/verifier
output or qualification report in this directory. A provider-backed run must
still pass every configured precision, recall, critical-case, indeterminate,
flip, and replay check for its exact composed identity. A human must then review
the candidate report and pin its path and digest before policy can consume it.

There is an earlier blocker: the 20 `reviewed_historical_units` rows point to
freshly generated fixture trees. Their semantics and labels can be source
reviewed, but they do not by themselves prove 20 real historical repository
misalignments. The independent review records that distinction. Do not promote
this corpus until those rows are replaced or backed by stable historical source
references that satisfy the human trust boundary in [EVC-10.1]. A strict
`mode="enforce"` loader pass proves the closed artifact shape, not that human
historical judgment.

## Preregistration boundary

- Owner: the repository owner accepts or rejects the corpus and any later
  qualification report.
- Source boundary: fixture trees, semantic labels, historical source refs, and
  control tags were fixed before any model output.
- Derived boundary: tree manifests, obligations, evidence, candidates, packet
  IDs, receipts, and corpus identity come from the provider-free production
  pipeline.
- Review boundary: `independent-review.md` records a source-only inspection of
  every clean/misaligned pair. It does not assess model quality.
- Required next action: replace or substantiate the synthetic historical rows;
  then run the model-backed evaluator to a new candidate path, inspect the
  report, and only then pin exact corpus/report hashes in enforce configuration.

## Coverage

- 20 distinct source-reviewed synthetic target tuples in the historical-row
  schema (real historical provenance remains blocked)
- 20 positive misaligned variants
- 20 clean negative variants
- all 12 closed control tags
- five critical cases, including one critical valid-but-vacuous reciprocal
  trace
- confirmed and missing-trace expected classifications
- explicit analyzer/verifier false-positive and false-negative stress intent
- indeterminate, uncached-flip, misleading-nearby-code, out-of-packet-decoy,
  omitted-disconfirming-evidence, and prompt-injection controls

Literal deletion of a mapping, backlink, bind, or binding-test relation is not
in this corpus. That remains a deterministic-readiness failure and must make
zero model calls.

## Reproduction

Write the mechanical artifacts from the reviewed source cases:

```text
uv run python tests/semantic_eval/v3/generate_qualification_candidate.py --write
```

Check that every generated byte still matches production derivation:

```text
uv run python tests/semantic_eval/v3/generate_qualification_candidate.py
uv run pytest tests/test_semantic_eval_corpus_v3.py -q
```

The generator deliberately does not create a semantic report and never
constructs an analyzer or verifier.
